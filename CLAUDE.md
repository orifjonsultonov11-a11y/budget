# Мой бюджет — контекст проекта

Личное PWA-приложение для учёта доходов и расходов с дневным лимитом. Заменяет «Умный счёт» (Money Manager, Realbyte) и добавляет к нему логику дневного лимита. Один пользователь, один iPhone, интерфейс на русском, валюта — только сум (UZS).

Отвечай пользователю по-русски. Пиши кратко, без воды.

## Принятые решения (не менять без согласования)

**Продукт**
- Вкладки: «Операции», «График», «Лимит», «Настройки».
- Операции: только «Расход» и «Доход». Переводов и счетов нет (пользователь от них отказался). Категория у каждой операции обязательна.
- Быстрый ввод — как в «Умном счёте»: «+», сумма на встроенной клавиатуре с калькулятором (+ − × ÷), «Далее», категория, при наличии — подкатегория, потом «Сохранить» или «Продолжить» (сохранить и сразу ввести следующую).
- Виды операций: «По дням», «Календарь», «По месяцам» (календарные месяцы). Неделя начинается с понедельника. Есть поиск по заметкам и категориям.
- PIN-код не нужен.
- Философия: всё, что в «Умном счёте» устраивает, повторяем как есть; улучшаем только то, что можно улучшить.

**Лимит** (ядро продукта, исходная идея пользователя)
- Сумма на период: месяц с N-го числа (по умолчанию 12-го) или свои даты.
- Лимит дня = сумма / число дней периода. Деление целочисленное и без остатка: `round(L*(i+1)/N) - round(L*i/N)`.
- Неистраченное копится отдельной строкой «Остатки», перерасход — «Недостаток» (отрицательное число). И то и другое переносится на следующие дни.
- В конце периода показывается итог, остаток или недостаток переходит в следующий период.
- «Потрачено за день» берётся из операций: расходы в категориях, у которых включён «в лимите». Доходы на лимит не влияют. По умолчанию все категории в лимите; пользователь выключает их сам (переключатель на категории; если выключена родительская, подкатегории тоже не считаются).
- День «не внесён», пока в нём нет ни одной операции. Такие дни подсвечиваются. «Внести 0» ставит отметку `zero[date]`.
- Подсказка «если делить поровну» показывается мелко, основной расчёт — накопительный.
- Сумму периода можно менять посреди периода, тогда весь период пересчитывается.
- Смена числа начала месяца или переход на режим «Месяц» применяется сразу: текущий период подгоняется под новое число, предыдущий обрезается до стыка (`realign()`).
- На экране «Категории и лимит» скрытые (архивные) категории не показываются.

**Графики** (вкладка «График»)
- Сделано: круговая диаграмма по категориям с процентами (неделя / месяц / год), детальная линия категории по месяцам и разбивка по подкатегориям, темп трат против прошлого месяца с прогнозом, доходы против расходов и % сбережений, «что растёт / падает» (только месяцы, где внесено 10+ расходов: в истории пользователя есть большие пропуски), тепловая карта по дням, средние траты по дням недели, дисциплина лимита (дней в лимите / перерасход / серия), топ по заметкам, крупные траты.
- Правила: цвет категории закреплён за самой категорией (слот по объёму трат за всё время), 8 цветов, остальное — серое «Другое». Никаких графиков с двумя осями Y. Подсказки по нажатию — через `data-tip`.

## Архитектура

Статичное PWA без сборки и зависимостей. Хостинг — GitHub Pages из ветки `main`, корень репозитория.

| Файл | Что это |
|---|---|
| `index.html` | разметка и весь CSS (дизайн-токены в `:root`, тёмная тема через `prefers-color-scheme`) |
| `app.js` | вся логика (ES5-стиль, IIFE, без фреймворков) |
| `sw.js` | service worker: офлайн-кэш, stale-while-revalidate |
| `manifest.webmanifest`, `icon-*.png` | установка на экран «Домой» |
| `sql-wasm.js`, `sql-wasm.wasm` | sql.js 1.10.3 — чтение файла `.mmbak` при импорте, грузится лениво |

**При каждом релизе увеличивай `CACHE` в `sw.js`** (`budget-v3` → `budget-v4` …). Добавил новый файл — добавь его в `FILES`. Обновление на телефоне применяется со второго запуска.

### Данные
- Хранение: IndexedDB `budget-app`, store `kv`, ключ `state`. Запасной вариант — localStorage `budget-app-v2`. Сохранение с задержкой через `persist()`, при уходе со страницы — сразу через `flush()`.
- Миграция: при первом запуске настройки лимита берутся из старой версии (localStorage `budget-tracker-v1`).
- Модель `D`:
  - `cats: [{id, name, type:'exp'|'inc', parent:null|id, order, archived, nl}]` — `nl: true` означает «не в лимите»; эмодзи хранится в начале `name`; глубина — максимум 2 уровня.
  - `tx: [{id, type, date:'YYYY-MM-DD', amount, cat, note, memo, t}]` — `amount` в целых сумах.
  - `limit: {mode:'month'|'custom', startDay, initialCarry, periods:[{start, end, limit}]}`.
  - `zero: {date: 1}`, `lastBackup`, `importedAt`.
- Кэш `C`: `cat` (по id), `byDate`, `slot` (цвет категории). Пересобирается через `rebuild()` после любой мутации.

### Рендер
- `render()` перерисовывает `#app` целиком, `renderOv()` — только оверлей (редактор, шторки). Анимация появления — только при открытии оверлея.
- События — делегированием: `data-act="..."` → функция в объекте `A`. Если функция возвращает `'ov'`, перерисовывается только оверлей.
- Черновики полей — `data-k` → `UI.d[k]`. Поля редактора — `data-e` → `UI.editor[...]`. Суммы — `data-money` (форматируются при вводе).
- Даты — строки `YYYY-MM-DD`, арифметика в UTC (`U()`, `addDays()`, `diff()`).

### Импорт из «Умного счёта» (`.mmbak` — это SQLite)
- `ZCATEGORY`: `ZUID`, `ZNAME`, `ZDOTYPE` (0 — доход, 1 — расход), `ZPUID` (родитель; `'0'` или null — верхний уровень), `ZISDEL` (→ `archived`), `ZORDER`.
- `ZINOUTCOME`: только `ZISDEL=0` и `ZDO_TYPE` 0 или 1 (3 и 4 — переводы, пропускаем). Дата — `ZTXDATESTR`; если пусто, то `ZDATE` (секунды от 2001-01-01, +978307200). Также `ZAMOUNT`, `ZCATEGORYUID`, `ZCONTENT` (→ `note`), `ZMEMO`.
- id получают префикс `mm:`. Повторный импорт заменяет операции и категории, а настройки лимита и флаги `nl` сохраняются.

### Резервная копия
JSON `{app:'budget', v:2, exported, data:D}`, сохраняется через меню «Поделиться» (`navigator.share` с файлом). Восстановление принимает и старый формат v1 (тогда переносятся только настройки лимита).

## Как проверять
- Локально: `python3 -m http.server` в корне репозитория, затем Playwright (Chromium, viewport 390×844). Время замораживай подменой `Date` в `add_init_script`.
- Проверяй светлую и тёмную темы, работу без сети (через service worker), импорт, резервную копию.
- Скриншоты смотри глазами: переполнение текста, наложения, обрезанные числа.

## Конфиденциальность — важно
Репозиторий публичный (этого требует GitHub Pages). **Никогда не коммить** файлы `.mmbak`, резервные копии `budget-*.json`, скриншоты с реальными данными и любые суммы и данные пользователя. Тестовые данные бери синтетические. Файл пользователя для тестов — только во временной папке вне репозитория.

## Рабочий процесс
- Изменения — в ветке, затем PR с кратким описанием на русском. Пользователь мержит, после чего Pages обновляется.
- Новое решение принято — обнови этот файл.
- Перед PR: `node --check app.js`, тест в Playwright, новая версия `CACHE` в `sw.js`.
